## Why this cut

* Reviewer behavior (S1, S2, S3) lives in src/lgtm/agents/, src/lgtm/review/, src/lgtm/diff/git_diff.py, src/lgtm/validation/evidence.py, src/lgtm/pipeline.py. S1 and S2 share section building and tool limits. S3 shares prompts.toml, authz_reviewer.py, and git_diff.py with them, so S3 follows S1/S2.
* The S3 grounding fix is in src/lgtm/validation/evidence.py (grounding checks cited code against added text only). src/lgtm/review/provenance.py only records config values in the run pin; it is touched by reviewer-reach when budget keys change, not by S3.
* S4, S7 and AC-S2-3 all change per-case results and metrics in benchmark/evaluate.py and benchmark/real_world/evaluate_real.py; they are one slice. AC-S2-3 sits here because the per-case result is written here.
* S5 and S6 share benchmark/judge_eval.py and the Kev judge code. S5-3 also changes scoring in benchmark/evaluate.py, so the slice follows benchmark-scope-trace. The supported/verdict rule lands in src/lgtm/validation/judge.py, src/lgtm/cli.py, and src/lgtm/reporting/report_builder.py. It has no Owns/Creates/Modifies overlap with pr-scoped-review (that slice does not change pipeline.py, report_builder.py, or judge files; kev-judge-measurement does not change pipeline.py or prompts.toml), so the prerequisite was dropped.
* No separate documentation slice: README and doc statements belong to the slice that makes them true.

## Decisions and the cut

DEC-5 to DEC-9 answer the open decisions; DEC-10 recommendations change criteria inside a slice, not the cut.

* Labels are generated by the build agent (DEC-8), so kev-judge-measurement does not wait on people.
* Real-world runs are held out (DEC-9) and run only by INTEGRATE: AC-S1-1, AC-S1-2, AC-S2-4, the litellm part of AC-S3-2, AC-S3-5, AC-S3-7, the real-world part of AC-S4-3 and AC-S4-5, the real-world part of AC-S6-1 and AC-S6-2, and AC-S6-6. Slice builders prove the logic with fixtures and stored runs.
