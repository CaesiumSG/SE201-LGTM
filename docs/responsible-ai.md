# Responsible AI: final risk assessment

This updates the checkpoint's risk table ([`checkpoint.md`](checkpoint.md)
§6) for the final system. It covers the risks of **LGTM itself**, the models
it runs at review time (Qwen3.8 27B as reviewer, Kev-4B as judge, optionally
a model on Amazon Bedrock). How we used AI tools to *build* the project is
disclosed separately in [`ai-log/`](../ai-log/README.md).

## Risk register

| Risk | What could go wrong | Mitigation in LGTM | Evidence | Residual risk |
|---|---|---|---|---|
| **Hallucination** | The reviewer invents a vulnerability, a code location or a policy rule | The evidence validator checks that every cited file, line range, snippet and policy quote exists in the committed snapshot. The Kev-4B judge then reads the cited code and marks each finding supported or not; unsupported findings are listed but do not fail the review | Final held-out run: 1 false alarm on 17 fix commits; Kev removed 5 findings on fix commits that would have been false alarms ([`deck-numbers.md`](deck-numbers.md), Extras) | The validator checks that evidence exists, not that it is relevant. The judge is itself a model (its verdict was right for 25 of 28 candidates in the component benchmark, against draft labels, and its severity for only 55%) |
| **Missed vulnerabilities and over-trust** | A clean report is read as "this PR is safe" | LGTM never approves or auto-merges; it reports, and a person decides. Out-of-scope classes are stated in the README. A candidate that was not judged, or an agent that failed, sets exit code 2 ("needs a person") rather than 0 | 2 of 17 held-out advisories were missed in every T=0 run; 6 sections in run 1 returned no parsable answer | Silence is not proof of safety, and users may still over-trust it. Scope is two classes (SQL injection and authorization) in Python web code |
| **Security of the tool: prompt injection** | Text in the PR (comments, docstrings, fake findings, names) talks the reviewer out of a finding | Comments and docstrings are stripped before the model sees PR code; reviewer-directed text is reported as a finding; the diff is labelled untrusted | 0 of 6 attacks succeeded in the final run ([`prompt-injection.md`](prompt-injection.md)) | Only the 6 attacks we wrote were tested; attacks that need no comment (misleading identifiers, plausible but wrong code) remain possible |
| **Security of the tool: policy tampering** | A PR edits the security policy so that its own change looks allowed | The policy index is built from the base commit and used only when it matches the base; a PR that changes policy docs is flagged for human review (and can fail the review with `fail_on_policy_change`) | Unit tests in `tests/test_policy_base.py` | A policy that was already wrong on the base branch is trusted |
| **Security of the tool: running untrusted code** | Reviewing a PR executes the attacker's code | Agent tools are read-only and sandboxed to the repository; PR code is read from committed snapshots and never executed or imported; tool calls have a budget | Guardrails in the README | The Semgrep and CodeGraph binaries parse untrusted files |
| **Privacy and confidentiality** | Private source code leaves the developer's machine | The default is a local model (Ollama on the developer's machine or the university GPU cluster), so code stays on hardware we control. The Bedrock backend is opt-in, needs its own token, and has a spending cap | Config default `llm_backend = "ollama"` | With Bedrock on, the diff and every file the agents read are sent to AWS. Our Bedrock runs used only public open-source code |
| **Bias in the evaluation** | Results look better than they are | Held-out advisories chosen after the last change and never tuned on; plain-LLM and Semgrep baselines on the same cases; three repeated runs; threats to validity written up | [`real-prs-eval.md`](real-prs-eval.md) | We chose the advisories (with AI-assisted search), so they over-represent flaws with one clear introducing commit. Advisories older than the model may be in its training data. Benchmark findings and component labels were labelled by Claude Opus 5.5; the component labels are not fully reviewed. Python web apps only |
| **Intellectual property** | We redistribute other projects' code, or present AI output as our own | Third-party repositories are cloned at run time into git-ignored caches and not committed, but the committed run records keep the agents' traces, including the tool output they read (code and documentation from the reviewed projects), so that results can be checked; Shoply and its cases were written for this project, and the OWASP-derived cases translate the OWASP Benchmark's injection patterns rather than copy its Java code. AI use in building the project is disclosed per member, and per commit where the commit carries an AI trailer | `.gitignore`; [`ai-log/`](../ai-log/README.md) | The committed run records (about 110 MB for the held-out runs of the final evaluation) contain excerpts of open-source code and documentation from the reviewed projects |
| **Responsible disclosure** | Publishing a real, unfixed vulnerability we found | The field trial's flagged PR and two live-hunt leads are withheld from this public repository until the maintainers have been told; only totals are published. The two live-hunt leads we name had already been published as advisories by others | `.gitignore` (final field-trial records); [`real-prs-eval.md`](real-prs-eval.md), live hunt | The withheld findings still need to be reported upstream |
| **Non-determinism** | The same PR gets different verdicts on different runs | Temperature 0 by default; repeated runs reported | All 17 held-out outcomes identical in three T=0 runs; T=1.0 lost one catch and added two false alarms | Irrelevant prompt changes have flipped single verdicts before ([`evaluation-log.md`](evaluation-log.md)); Claude on Bedrock ran at the provider's default temperature and varied between runs |
| **Cost** | Review cost grows with model size | The default model runs on hardware we already have; Bedrock spend is metered per call against a budget | Final evaluation: USD 101.72 on Bedrock, the Qwen runs on the university cluster | GPU hours were not logged; LGTM takes about 2 minutes per diff against 7 seconds for a plain LLM call |

## What we would do before real use

- Report the withheld findings to their maintainers.
- Have the team review the AI-drafted component labels and re-score.
- Grow the held-out set beyond 17 advisories and add languages other than
  Python.
- Measure real token use per review (the proposal's metric; the final run
  recorded only an estimate, and PR #41 adds real counts).
