# AI Use Disclosure Log

The course allows AI tools during development but requires us to track
their use. Each member's own log, in the format the policy asks for, is
in [`ai-log/`](../ai-log/README.md) (one file per member). This log covers **AI used to build the project**, collated at
team level by area of work. The LLM that LGTM runs at review time (Qwen via
Ollama) is part of the product; its risks are covered in the checkpoint
report's Responsible AI section.

Tools used by the team: **Claude Code** (Anthropic; Opus 5.5 / Sonnet 5.5
/ Fable 5) for most implementation and documentation, **GitHub Copilot**
for the GPU model server, and **Google Antigravity** (Gemini Flash 3.8)
for the prompt-injection red-teaming. All AI-generated code went through a
pull request reviewed by a team member before reaching `main`.

## What we learned about using AI tools to build this

- **Fast to scaffold, but you must check the evaluation.** The AI-generated
  pipeline worked end to end on day one. The subtle problems were in the
  *evaluation*: a scoring fallback that credited the wrong agent, and a
  baseline that didn't match the proposal. Neither was caught by unit
  tests, because the tests encoded the same assumptions. Review your metrics
  code as carefully as your product code.
- **Plausible ≠ correct.** The AI-written "llm-only" baseline looked
  reasonable and ran fine, yet it quietly gave the baseline the same RAG
  and tools as LGTM, so the comparison could not show what those
  components add. Checking implementation against the written spec, line
  by line, is what found it.
- **Keep a human in the loop on claims.** Every number in the README and
  reports is copied from `summary.json` files in `benchmark/runs/`, so a
  reader can trace each claim to a run.
